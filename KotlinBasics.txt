1. Null Safety ⭐⭐⭐

This is probably the most important Kotlin feature for a Java developer.

The problem in Java

Consider:

String name = null;

System.out.println(name.length());

Runtime:

NullPointerException

You only discover the problem when the program runs.

Kotlin's approach

Kotlin separates:

Non-null
Nullable
Non-null
var name: String = "Karan"

You cannot do:

name = null

Compiler error.

Nullable

If you want a variable to contain null, explicitly say so:

var name: String? = null

The ? means:

This variable is allowed to contain null.

Safe call ?.

Suppose:

var name: String? = null

This is not allowed:

println(name.length)

Instead:

println(name?.length)

If name is:

"Karan"

result:

5

If name is:

null

result:

null

No NullPointerException.

Elvis operator ?:

Very useful.

val length = name?.length ?: 0

Meaning:

name exists?
   ↓
YES → name.length
   ↓
NO → 0

Example:

val displayName = name ?: "Unknown"

If:

name = "Karan"

then:

displayName = "Karan"

If:

name = null

then:

displayName = "Unknown"
Java equivalent

You might write:

String displayName = name != null ? name : "Unknown";

Kotlin:

val displayName = name ?: "Unknown"
!! — force non-null

You can tell Kotlin:

"I guarantee this isn't null."

val length = name!!.length

But be careful.

If name == null:

KotlinNullPointerException

So:

?.

is generally safer than:

!!
Mental model
String
   ↓
Cannot be null

String?
   ↓

?.
   ↓

   ↓

   ↓

        2. Lambda ⭐⭐⭐

A lambda is basically:

A function without a name that can be stored in a variable or passed around.

You know Java already has something similar with lambda expressions.

Java
(x) -> x * 2
Kotlin
{ x -> x * 2 }

Example:

val double = { x: Int -> x * 2 }

Output:

10

Think:

Normal function

fun double(x: Int): Int {
    return x * 2
}

versus:

Lambda

{ x: Int -> x * 2 }
Lambda syntax

Basic:

{ parameter -> body }

Example:

val add = { a: Int, b: Int -> a + b }

Call:

add(10, 20)

Result:

30
Why is this useful?

Because you can pass behavior around.

For example:

    println(number)
}

Here:

{ number ->
    println(number)
}

is a lambda.

Instead of telling forEach:

"Here is a function name."

you give it:

"Here is the behavior you should execute."

This becomes extremely important in Android callbacks, collections, event listeners, etc.

3. Higher-order functions ⭐⭐⭐

This sounds complicated but the concept is simple.

A higher-order function is a function that:

accepts another function as a parameter, OR
returns a function.
Example
fun calculate(
    a: Int,
    b: Int,
    operation: (Int, Int) -> Int
): Int {
    return operation(a, b)
}

Here:

operation: (Int, Int) -> Int

means:

operation is a function that takes two Ints and returns an Int.

Now:

val result = calculate(10, 5) { a, b ->
    a + b
}

Result:

15

You can change the behavior:

val result = calculate(10, 5) { a, b ->
    a * b
}

Result:

50

Same function.

Different behavior.

Java comparison

Modern Java:

int calculate(
    int a,
    int b,
    BiFunction<Integer, Integer, Integer> operation
)

Kotlin makes function types much more natural:

operation: (Int, Int) -> Int

This is one reason Kotlin code often feels cleaner.

        Now let's understand destructuring

This sounds complicated but it's actually very simple.

Normal situation

Suppose you have a patient:

data class Patient(
    val id: Int,
    val name: String,
    val age: Int
)

Create one:

val patient = Patient(
    101,
    "Karan",
    21
)

Normally, if you want the details:

println(patient.id)
println(patient.name)
println(patient.age)
Destructuring says:

"Take this object's individual values and put them into separate variables."

Instead of:

val id = patient.id
val name = patient.name
val age = patient.age

you can write:

val (id, name, age) = patient

Now Kotlin has:

id   → 101
name → Karan
age  → 21

That's destructuring.

6. Real-life scenario

Imagine you're at a hospital reception.

A patient arrives carrying this information:

Patient
----------------
ID      : 101
Name    : Karan
Age     : 21

Normally, the receptionist asks:

Give me the ID
Give me the name
Give me the age

In Kotlin:

val id = patient.id
val name = patient.name
val age = patient.age

Destructuring is like saying:

"Give me all three pieces separately."

val (id, name, age) = patient

Now you have the three variables immediately.

7. How does Kotlin actually do this?

Remember when we discussed data class?

data class Patient(
    val id: Int,
    val name: String,
    val age: Int
)

A data class automatically generates component functions conceptually like:

component1()
component2()
component3()

So:

val (id, name, age) = patient

is conceptually like:

val id = patient.component1()
val name = patient.component2()
val age = patient.component3()

And:

component1() → id
component2() → name
component3() → age

You normally don't call these manually.

8. You don't have to take everything

Suppose you only need:

id
name

You can do:

val (id, name, _) = patient

The _ means:

"I don't need this value."

So:

id   → 101
name → Karan
_    → ignore age

        Scope functions — simple scenario

Imagine you are creating a Student object.

Start with apply() ⭐

Read it like English:

"Create a Student, and apply these changes to it."

After this:

student
┌───────────────┐
│ name = Karan  │
│ age  = 21     │
└───────────────┘

So apply is mainly:

Configure an object.

Why can I directly write name?

Inside:

.apply {
    name = "Karan"
    age = 21
}

Kotlin automatically makes the object the context (this).

Conceptually:

student.apply {
    this.name = "Karan"
    this.age = 21
}

So:

name = "Karan"

is basically:

this.name = "Karan"

Now let() ⭐

Imagine you already have:

val student = Student("Karan", 21)

You want to temporarily work with the student.

student.let {
    println(it.name)
    println(it.age)
}

Read it as:

"Take this student and let me work with it inside this block."

Here the object is represented by:

it

So:

student.let {
    println(it.name)
}

means roughly:

Take student
     ↓
give it to `it`
     ↓
use it inside the block
Why is let particularly useful with null?

This is where you'll see it a lot.

val name: String? = "Karan"

Because it's nullable, you shouldn't directly do:

name.length

Instead:

name?.let {
    println(it.length)
}

Read:

"If name is not null, let me work with it."

If:

name = "Karan"

the block executes.

If:

name = null

the block doesn't execute.

So apply vs let

This is the first thing you should memorize:

apply
val student = Student("", 0).apply {
    name = "Karan"
    age = 21
}

Purpose:

Configure/change the object.

Inside the block:

this → object
let
student.let {
    println(it.name)
}

Purpose:

Work with/use the object temporarily.

Inside the block:

it → object
Now imagine a restaurant 🍔

This makes scope functions easier to remember.

You order a burger.

Burger object
apply

You are customizing the burger:

Burger
 ↓
apply
 ↓
Add cheese
Add sauce
Remove onion

That's:

Configure the object.

let

The burger is ready and you want to do something with it:

Burger
 ↓
let
 ↓
Eat it
Take a photo
Print its price

That's:

Use the object.

What about also?

also means:

"Do something extra with this object."

Example:

val student = Student("Karan", 21)
    .also {
        println("Student created: ${it.name}")
    }

The student is still the main object.

You're just doing an additional action.

Think:

Student
   ↓
also
   ↓
Log / print / debug / extra action
What about run?

Don't worry about this one yet.

You can think of:

student.run {
    println(name)
    println(age)
}

as:

"Run this block of code using this object."

Inside:

this → student

It's similar to apply in how you access properties, but the purpose/return value differs.

What about with?

Same idea:

with(student) {
    println(name)
    println(age)
}

Read:

"With this student, do these things."

It's not called using:

student.with

Instead:

with(student) {
    ...
}
Don't memorize five definitions

Instead remember this little story:

I have a Student object
        │
        ├── apply → "Configure my student"
        │
        ├── let   → "Let me use my student"
        │
        ├── also  → "Also do something with my student"
        │
        ├── run   → "Run this code with my student"
        │
        └── with  → "With my student, do this"

And remember the object reference:

Function	Inside block	Simple meaning
let	it	Use object
run	this	Run code with object
with	this	Work with object
apply	this	Configure object
also	it	Do something extra
⭐ For now, only learn these 3

Since you're coming from Java, don't overload yourself.

1. apply → configure
val student = Student("", 0).apply {
    name = "Karan"
    age = 21
}
2. let → use
student.let {
    println(it.name)
}
3. also → extra action
val student = Student("Karan", 21).also {
    println("Created ${it.name}")
}

Once these feel natural, run and with become much easier.

The one sentence to remember:

Scope functions don't create a new special kind of object — they simply give you a convenient temporary scope to work with an existing object.

    1. Coroutines ⭐⭐⭐


First: what problem are coroutines solving?

Suppose your Android app needs to call:

GET /patients/101

The server may take:

500 ms
2 seconds
5 seconds

You cannot block the Android main/UI thread waiting for it.

Why?

The main thread is responsible for things like:

Drawing UI
Handling button clicks
Scrolling
Animations
Touch events

If you do a slow operation there:

UI Thread
   ↓
API call
   ↓
WAIT...
   ↓
WAIT...
   ↓
WAIT...

The app can freeze.

Coroutine = a lightweight way to perform asynchronous work

Instead of:

UI thread
   ↓
WAIT for API
   ↓
continue

you can do:

UI
 ↓
start coroutine
 ↓
API work happens without blocking UI
 ↓
result comes back
 ↓
update UI

Example:

CoroutineScope(Dispatchers.IO).launch {
    val patient = getPatientFromApi()

    println(patient)
}

The important word here is:

launch

It starts a coroutine.

Extension Functions

One of Kotlin's most useful features.

Suppose you have:

fun String.firstCharacter(): Char {
    return this[0]
}

Now:

val name = "Karaneesh"

println(name.firstCharacter())

It looks like firstCharacter() belongs to String.

But you didn't modify the String class.

You're extending its functionality externally.

Another example
fun Int.isEven(): Boolean {
    return this % 2 == 0
}

Then:

println(10.isEven())

Output:

true

this refers to the object on which the extension function is called.

10.isEven()
 ↑
 this

Important:

Extension functions don't actually modify the original class.

They are resolved statically by the compiler.

27. Lambdas

A lambda is a function without a name.

Normal function:

fun add(a: Int, b: Int): Int {
    return a + b
}

Lambda:

val add = { a: Int, b: Int ->
    a + b
}

Call:

println(add(10, 20))

Result:

30

Basic structure:

{ parameters -> body }

Example:

val greet = { name: String ->
    println("Hello $name")
}

Call:

greet("Karaneesh")

Higher-Order Functions

A higher-order function is a function that either:

accepts another function as a parameter, or
returns a function.

Most commonly you'll see the first.

Example:

fun calculate(
    a: Int,
    b: Int,
    operation: (Int, Int) -> Int
): Int {

    return operation(a, b)
}

Now:

val result = calculate(10, 20) { x, y ->
    x + y
}

The flow is:

calculate()
   ↓
receives 10
   ↓
receives 20
   ↓
receives lambda
   ↓
operation(10,20)
   ↓
30

The type:

(Int, Int) -> Int

means:

takes Int + Int
        ↓
returns Int

Another:

(String) -> Unit

means:

takes String
    ↓
returns Unit

This concept is extremely important for Android and Kotlin because you'll see it everywhere:

button.setOnClickListener {
    // ...
}

The lambda is being passed as behavior.
